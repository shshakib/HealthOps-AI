# v0.2.0 — Local portfolio preview

HealthOps reads synthetic patient records, checks a limited set of trial criteria,
shows the source evidence and unknowns, and lets an authenticated reviewer record
the next screening step. This release packages the working local workflow for a
portfolio demonstration.

- Local accounts with Viewer, Reviewer, and Admin permissions; attributable review history.
- Optional read-only evidence assistant with OpenAI, Claude, Gemini, and Ollama adapters.
- Local MLflow traces and versioned evaluations with measured usage, latency, and cost.
- A two-minute captioned interface recording using an isolated, explicitly simulated review.
- Reproducible new fixtures and preserved evaluation failures, with a Docker-ready CLI dataset option.

Validation: 144 Python tests, nine browser workflows, and the offline evaluation
covering 22 answers, six scripted failures, and 15 API permission boundaries.
The fresh dataset adds 24 questions across six profiles. Original v3 live regression:
22/22. Fresh v3 first pass: **23/24**. A prompt-only v4 experiment passed 21/24 and
was rejected; this release retains v3. Full reports explain the safe fallbacks,
costs, and limitations rather than hiding them.

Read the [fresh evaluation](../evaluation/fresh/README.md),
[demo walkthrough](../demo/walkthrough.md), and [startup instructions](../../README.md).
The attached `healthops-demo.webm` shows evidence-only mode, not a live model call.

This is a **prerelease local portfolio application** using synthetic data. Actual
registry interpretations and final product acceptance remain subject to human
review. There is no independent clinical benchmark, production deployment,
enterprise SSO, or automated enrollment. Only OpenAI has a published real-provider
evaluation; other adapters have protocol tests. MIT covers the original code;
third-party records and dependencies retain their own notices.
